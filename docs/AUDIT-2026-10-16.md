## Validation et limites

Tests locaux sur fixtures : scénarios commerciaux existants, migrations et contraintes PostgreSQL via PGlite, conflits isolés, préservation des credentials, commandes ciblées, PDF/antivirus, limitations anonymes et travail bcrypt pour les comptes inconnus. TypeScript, ESLint et build de production passent. L’audit npm de production signale zéro vulnérabilité ; l’audit complet conserve sept alertes de développement dans la chaîne braces, après correction de postcss-selector-parser. Les tests HTTP du serveur compilé avec PostgreSQL/PGlite via protocole réseau vérifient nonces, HSTS, rôles, propriétaire, Range, révocation de document/session, ETags et refus d’origine hostile.

Le navigateur Chromium ne peut pas être téléchargé dans cet environnement : l’archive distante reçue est invalide. Le parcours Playwright est découvert/compilé localement et ajouté à CI avec un vrai service PostgreSQL ; son exécution doit être vérifiée dans GitHub avant promotion. Le premier parcours navigateur CI a validé l’inscription passkey, les connexions client, le CSRF et les médias, puis révélé une boucle entre connexion client et portail administrateur : la redirection a été corrigée et le parcours complet doit être vert avant promotion. Aucun résultat complet de navigateur, CodeQL, ZAP, test de charge ou pentest non exécuté n’est inventé.

L’audit npm complet distingue les outils de développement des dépendances déployées. Les chaînes Tailwind 3 / ESLint Next utilisent encore braces 3.0.3 : GHSA-vfj7-8cjw-p6xm n’a pas de version corrigée publiée lors de cette vérification. Le rapport complet doit être revu et les chemins d’entrée des outils restent des sources/configurations de confiance ; ne jamais analyser des patterns d’un visiteur dans ces outils. Une migration majeure du pipeline CSS/lint nécessite validation visuelle et ne doit pas être confondue avec un patch des dépendances runtime.

`docs/release-evidence.example.json` reste volontairement non attesté. Seul l’exploitant peut fournir les preuves réelles, contacts et dates. `ops:check` refuse un registre absent ou incomplet ; cocher des cases n’est pas une preuve technique et ne remplace pas les pièces justificatives.
