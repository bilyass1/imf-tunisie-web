# تقرير مراجعة مشروع IMF

تاريخ المراجعة: 18 سبتمبر 2026

## النتيجة

تم تنفيذ تحسينات في الأمان والموثوقية والأداء وتجهيز الموقع كتطبيق ويب قابل للتثبيت PWA. نجح بناء المشروع واختبارات الانحدار، وتم تشغيل النسخة الجديدة محليًا على http://127.0.0.1:3100. لم يتم النشر على GitHub أو تحديث الموقع العام.

هذه النتيجة لا تعني خلو المشروع من جميع العيوب أو جاهزيته لأي عدد من المستخدمين. التخزين الحالي يعتمد على ملف JSON وملفات محلية، ويحتاج إلى ترحيل قبل تشغيل عدة خوادم.

## تجهيز PWA

- إضافة ملف تعريف التطبيق، الاسم، الألوان، الأيقونات وأيقونة مناسبة للقناع.
- إضافة عامل خدمة Service Worker وشاشة عامة عند انقطاع الإنترنت.
- إظهار طلب تثبيت في المتصفحات الداعمة، وإرشاد مستخدمي iOS للإضافة إلى الشاشة الرئيسية.
- اقتصار Cache Storage على الأيقونات وشاشة عدم الاتصال. لا تُخزَّن العقود أو الرسائل أو صفحات الحسابات أو استجابات API أو طلبات الحفظ فيه.
- الحسابات والرسائل والمستندات تحتاج اتصالًا؛ لم تتم إضافة إرسال مؤجل للطلبات الحساسة.
- يجب استخدام HTTPS في النشر العام. المتصفح والمستخدم يتحكمان في الموافقة على التثبيت؛ لا يمكن فرض تثبيت صامت.

تم التأكد من استجابة الموقع والـmanifest وعامل الخدمة وصفحة عدم الاتصال والأيقونات بالحالة HTTP 200، ومن وجود رابط manifest في الصفحة. لم يُجرَ تثبيت فعلي على Android أو iPhone، ولم يُحاكَ انقطاع الشبكة داخل متصفح فعلي؛ استراتيجية الانقطاع اختُبرت برمجيًا.

## الاختبارات المنجزة

- نجاح تجميع المشروع وفحص TypeScript وتوليد 99 صفحة ثابتة أثناء البناء، إضافة إلى المسارات الديناميكية.
- تبادل الرسائل: عميل ← تجاري ← عميل، وعزل المستلمين، ورفض الرسائل الفارغة والطويلة والطلبات دون جلسة.
- إنشاء وتعديل الحسابات، منع تكرار البريد وتعارض إسناد الشقة، واختبارات تغيير كلمات المرور.
- التحكم في الوصول للمستندات والصور الخاصة، وسحب الوصول بعد حذف المستند وإعادته عند الاسترجاع.
- رفض الكتابة عند غياب التخزين الدائم، وعزل نسخ البيانات، وعدم استبدال ملف تالف ببيانات تجريبية.
- عدم إدخال طلبات POST أو API أو المستندات الخاصة في ذاكرة PWA، واستخدام شاشة عامة عند انقطاع الاتصال.
- npm audit: صفر ثغرات معروفة وقت الفحص. هذه النتيجة لا تعوض مراجعة أمنية شاملة.

الاختبارات الآلية تعمل ببيانات منفصلة؛ لم تُرسل رسائل اختبار إلى عملاء حقيقيين. أمر lint الحالي يتحقق من TypeScript ولا يمثل فحص ESLint كاملًا.

## ما يلزم للتوسع الحقيقي

1. نقل البيانات إلى PostgreSQL، مع معاملات وقواعد فريدة للبريد وإسناد الوحدات، بدل إعادة كتابة ملف JSON كامل.
2. نقل العقود والصور إلى تخزين كائنات دائم، وفصل الملفات الخاصة عن العامة، مع تحقق الصلاحيات قبل تنزيل الملفات الخاصة.
3. تقسيم قوائم العملاء والمحادثات إلى صفحات، وتجنب تحميل السجل الكامل لكل العملاء في الواجهة التجارية.
4. إضافة تحديد موزع لمحاولات تسجيل الدخول والإرسال والرفع، وسجل تدقيق يحدد الموظف الذي أجرى كل تعديل.
5. إزالة حسابات العرض التجريبي قبل الاستخدام العام، وتوفير حسابات موظفين منفصلة ومفتاح AUTH_SECRET قوي في الاستضافة.
6. إعداد نسخ احتياطية واختبار الاسترجاع، ومراقبة الأخطاء، واختبارات ضغط بأعداد مستخدمين وأحجام ملفات ممثلة للاستخدام الفعلي.

لا يُنصح بتشغيل عدة عمليات كتابة على قاعدة JSON الحالية. وظائف الإدارة تحتاج تخزينًا دائمًا؛ لا تصبح مناسبة تلقائيًا لاستضافة Vercel أو أي استضافة ذات قرص مؤقت بمجرد إضافة PWA.

## الحالة النهائية

الإصلاحات المذكورة مفعلة على المعاينة المحلية. بقيت البنية الأساسية للتخزين المحلي كما هي؛ لم تُنفذ هجرة PostgreSQL أو التخزين السحابي لعدم وجود خدمة مهيأة ضمن المشروع. لا توجد نتائج قياس ضغط أو ضمانات عدد مستخدمين في هذا التقرير.
